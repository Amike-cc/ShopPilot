## 5. 结构约定（本轮新增代码一律遵守）

- **纯逻辑模块**：`tab-close-plan.ts`（main）、`tabs-batch-close.ts` / `tab-bar-actions.ts` / `image-text-analysis.ts` / `store-group.ts` / `product-link-actions.ts`（renderer）全部**零 electron / vue / DOM / node 内置依赖**，只导出纯函数与类型，因此可以直接单测。
- **接口方向单一**：组件 → store 方法 → preload bridge → IPC；纯模块只被上层调用，不反向 import 组件或 IPC。
- **错误处理不吞**：IPC 失败一律 `toast('<动作>失败: ' + message)`；确认类交互一律用**页内浮层**，不用 `window.confirm/prompt`（会阻塞渲染进程并卡死 CDP 验收）。
- **验收脚本也分层**：`tools/acceptance/cdp-client.js` 只管「连 CDP → 求值 → 断言收集」，启动/清理/业务断言留在各自的验收脚本里。
- 一个已知的**双份口径**（不影响正确性，留给后续清理）：`tab-close-plan.ts` 的 `TabClosePlan.remaining` 按「关闭前快照」算，而 `window-manager.closeTabs()` 关闭后按 live state 重数并以此为准（`closeTab` 可能因为页面正在销毁而失败）。当前没有消费方读计划里的那份值。
