# 商品管理 · 重新设计（v4 · 现状重构版）

> **状态**：设计方案（待评审，未开工）　**日期**：2026-10-15　**基线**：v0.4.66（商品域 M1–M5 已落地）
> **上游文档**：`docs/product-management-plan.md`（v3，数据模型 / 同步 / 发布的设计**仍然有效**）、`docs/product-profiles.md`（四平台真机实测档案）
> **定位**：v3 解决"从 0 到 1"（能不能同步、能不能半自动发布）；本版解决"从 1 到好用"——
> 以**日常增删改查与批量操作**为中心，重排信息架构，补齐 列表 / 筛选 / 排序 / 分页 / 状态 / 批量 六个缺口。
>
> **四条铁律不变（v3 §15 的 D2/D3/D4/D10）**：发布永远由用户在浏览器里提交；平台商品与本地商品不自动合并；
> 平台值与本地值冲突不覆盖；抓不到就如实说（不猜、不兜底）。

## 0. 摘要（只读这一节也能理解本方案）

### 0.1 一句话

把「商品管理」从"同步 + 发布的功能演示页"改造成"每天都要打开的商品台账"：
**本地商品**是一等公民（可新增、编辑、删除、查询、批量操作），**平台商品**是它的观测面与挂载面，
发布动作从行操作 / 批量条进入**独立的右侧向导**——不再把 5 个面板堆在页面下方。

### 0.2 十个核心决策

| # | 决策 | 一句话理由 |
| --- | --- | --- |
| R1 | 主视图 = 本地商品列表；平台商品、回收站为平级 Tab | 本地商品是可操作的主数据；现在两张平表并列、没有主次 |

## 1. 核心目标与使用场景

### 1.1 核心目标（按优先级）

1. **台账可信**：界面上的每个数字要么来自平台 / 本地事实，要么明确标注"未取到 / 未实测 / 未归并"——延续项目"如实说明"风格；状态、挂载、同步健康三处口径一致、互不矛盾。
2. **日常好用**：找一件货 ≤ 3 步（筛选 → 看清 → 动作）；批量改价 / 归档 ≤ 4 步（选 → 预览 → 确认 → 回执）。
3. **操作安全**：删除可恢复、批量可预览、发布永远人工提交、写操作全部有审计。
4. **能力不缩水**（承接 v3）：同步、归并、半自动发布、回读闭环、图片本地化、孤儿清理全部保留，不因重构回退。

### 1.2 使用场景（设计围绕这 5 件事，按发生频率排序）

| # | 场景 | 谁 | 什么时候 | 期望路径 |
| --- | --- | --- | --- | --- |
| A | **开店后看一眼** | 运营 | 每天打开应用 | 3 秒内看到：各店同步健康 / 待归并条数 / 缺图条数 / 未就绪条数；异常一键跳到对应筛选 |
| B | **找货** | 运营 | 被问"那款沙发还有货吗、多少钱" | 搜索（标题 / SKU 码 / 条码）+ 状态 / 平台筛选 → 列表行直接看到价格区间与总库存 → 点开详情 |
| C | **批量调整** | 运营 | 换季调价 / 批量打"清仓"标签 / 批量归档停售品 | 多选 → 批量条 → 预览 diff → 确认 → 回执（成功 / 跳过 / 失败数） |
| D | **补内容再发布** | 运营 | 新品上架 | 新建或另存 → 编辑器补齐（图 / 描述 / 规格）→ 发布向导（预检 → 预填 → 人工提交 → 回读建议） |
| E | **收尾清理** | 运营 | 月度整理 | 归档停售品、回收站恢复误删、导出 CSV 交汇报 |

### 1.3 非目标

- 不做：平台类目 / 资质自动匹配、无人值守发布、平台反向实时回写、跨平台库存双向同步、买家信息采集、营销域（同 v3 §1.2）。
- 本版也不做：多选跨页选择超过 500 条、批量撤销（改价可反向再算一次，不提供时间机器）、图片编辑（裁剪 / 水印，属图片工作台）。

## 3. 功能设计：增、删、改、查、批量

### 3.1 查询（Query）

**入口**（本地商品 Tab）：

- 搜索框：标题 / SKU 码 / 条码（三字段 OR），防抖 300ms，长度 <2 提示"至少输入 2 个字符"；
- 筛选：状态（全部 / 草稿 / 就绪 / 已归档）× 挂载（全部 / 已挂载 / 未挂载）× 平台（有链接的平台）；
- 排序：更新时间（默认）/ 创建时间 / 标题 / 价格（按变体最低价）/ 库存合计；
- 分页：页码 + 每页 20/50/100；显示"共 N 条"。

**行为**：每次查询把 query 对象发到主进程（Zod 白名单）→ 仓储参数化 SQL。**排序字段只允许映射表内的固定值**（绝不把用户输入拼进 ORDER BY）。

**空态如实区分**（延续项目风格）：`还没有商品（新建一个 / 从平台商品另存）` ≠ `当前筛选没有匹配（清除筛选）`——两种空文案不同。

### 3.2 新增（Create）

| 路径 | 入口 | 行为 | 初始状态 |
| --- | --- | --- | --- |
| A · 新建空白 | 页头「新建商品」 | 对话框：标题（必填）＋ 目标平台提示（可选，仅提示该平台必填项，不写值）→ 创建后**直接打开编辑器** | draft（无变体=有 blocker） |
| B · 复制商品 | 行操作 ⋯ →「复制」 | 复制 draft（变体重生成 id；媒体**复用 sha256 文件与 local_path**，只新增引用行，不重复下载）；标题自动加「（副本）」 | 按内容重算 |
| C · 从平台另存为 | 平台商品行（保留现状） | 已有能力不动 | 按内容重算 |

- 三条路径都写审计：`product.library.create` / `product.library.duplicate` /（C 沿用现有）。
- 约束：新建标题上限 60 字（各平台最严口径，v3 §6.1），超长即时提示。

### 3.3 编辑（Update）

**编辑器从"两栏草稿"升级为四分区**（对齐 `product_library_save` 已支持的完整 draft）：

| 分区 | 字段 | 说明 |
| --- | --- | --- |
| ① 基础 | 标题*、副标题、品牌、本地分类、标签 | 标签为 chip 输入（≤30 个，每个 ≤30 字） |
| ② 媒体 | 封面（1）+ 图集 + 详情图 | 设封面 / 拖拽排序 / 移除引用 / **添加本地图片**（文件对话框 → 主进程校验类型与大小后入 product-media，origin='local'） |
| ③ 规格 | 变体行：规格文本、价格（元）、库存、SKU 码、条码 | 增 / 删 / 改行；规格文本按 v3 §5.6 的"不猜"规则解析（`颜色:红;尺码:L`），解析不出则整串保留 |
| ④ 校验 | `productDraftIssues` 分级实时展示（blocker / warning / info） | 已有能力，直接挂到编辑器 |

- 保存 = 全量草稿替换（沿用现有 `save` 语义）→ 重算 `draft_hash` → 重算状态 → 回执 issues。
- **已归档商品只读**：点编辑提示"已归档，先取消归档"；归档商品的操作只保留：取消归档 / 导出 / 删除。
- 约束：媒体移除只删"引用行"，文件进入孤儿候选（由现有孤儿清理处理，绝不直接删文件）。

### 3.4 删除与恢复（Delete / Restore）

| 操作 | 入口 | 行为 | 约束 |
| --- | --- | --- | --- |
| 删除（软删） | 行操作 / 批量条 | **确认弹层**（写明：移入回收站、可恢复、发布台账保留；若该商品有挂载，额外说明"其平台商品将回到未归并"——现状 softDelete 就会解绑） | 单条无上限；批量 ≤100/次 |
| 回收站 | 本地商品 Tab 旁 | 列：标题 / 删除时间 / 发布记录数；操作：恢复 | 恢复 = 清 `deleted_at` + 重算状态；**不自动重新归并**（D2），确认弹层说明 |
| 彻底删除 | 回收站行操作 | 仅当该商品**无任何发布记录**（无 publish job）时可彻底删除（级联 variants/media 行）；有发布证据则按钮禁用并给出原因 | 审计 `product.library.purge`；只删行，**不删磁盘文件**（孤儿清理负责） |

### 3.5 批量操作（Batch）

**通用协议**（所有批量一致）：多选（当前页全选 + 跨页保留选择，上限 500）→ 批量条出现 → 选择操作 → **预览**（影响面 + 样例 diff + 将被跳过的项）→ 确认执行 → 回执（成功 / 跳过 / 失败明细）→ 审计（只记计数）。

| 操作 | 参数 | 上限 | 规则要点 |
| --- | --- | --- | --- |
| 批量改价 | 模式（按百分比 % / 按固定金额 ± 元）；数值；最低价保护 | 200 商品 | 作用于每个变体；`new = max(round(old×(1+p/100)) 或 old+Δ, 1 分)`；null 价格跳过并计数（见附录 A） |
| 批量加 / 删标签 | 标签集（≤10 个） | 500 商品 | 去重合并；不改其他标签 |
| 批量归档 / 取消归档 | — | 500 商品 | 归档→只读；取消归档→按内容重算 |
| 批量删除 | — | 100 商品 | 同 3.4 软删，带确认 |
| 批量导出 CSV | 范围（选中 / 当前筛选全量） | 无硬上限（>5000 行提示耗时） | 见 §4.6 / R3 |

- 批量改价后**重算 draft_hash**（价格变了 → 指纹变 → 发布预检会如实提示"内容有更新"）。
- 不提供"撤销"：预览与回执里如实说明"可反向再调一次"。

### 4.2 筛选与排序（参数级规格）

| 视图 | 筛选 | 排序（白名单） | 默认 |
| --- | --- | --- | --- |
| 本地商品 | status（draft/ready/archived，多选）· linked（any/linked/unlinked）· platform · keyword | updated / created / title / priceMin / stockTotal（±） | 排除归档；updated DESC |
| 平台商品 | storeId · platform · platformStatus · onlyOrphan · keyword | collected / platformUpdated / title / price（±） | collected DESC |
| 回收站 | keyword | deletedAt DESC | — |

实现纪律：筛选拼参数化 WHERE；排序用 `SORT_SQL` 映射表（字段名 → 固定 SQL 片段），未知值直接拒绝。

### 4.3 分页

- Offset 分页（`limit` ≤ 200 / `offset` ≤ 100k，沿用现约束）+ `total` 计数；页大小 20 / 50 / 100（默认 50）。
- 数据量级参考：v3 §4.11 估算单店 1k–1w 商品；offset 在 10 万行内无性能问题，**不引入游标分页**（复杂度换不到收益）。
- 翻页保留筛选与选择集；返回顶部。

### 4.4 状态管理

**有效状态集**（重定义后）：`draft`（草稿）· `ready`（就绪）· `archived`（已归档，**显式**）。
`published` 不再作为主状态写入（语义由「挂载」列承担）；枚举保留在 CHECK 里，避免为它做迁移。

**重算规则**（纯函数 `deriveProductStatus(draft, issues, { archived })`）：

```
archived === true                          → archived
issues.some(level === 'blocker')           → draft
否则                                        → ready
```

**单点维护协议**（防死字段复发）：

- 唯一入口 `recomputeProductStatus(productId)`；调用点仅限：`create` / `duplicate` / `save` / `saveAsLocal` / `restore` / `archive(toggle)`。
- `merge` / `unmerge` **不改状态**（挂载是链接属性，不是商品状态）。
- **不变量测试**：`tests/unit/product-status-recompute.test.ts` —— ① 规则函数分级正确；② 源码级断言 save/create 等写路径调用了 recompute（防回归成死字段，沿用 `product-status-vocabulary.test.ts` 的源码扫描手法）。
- 存量回填：升级后首次启动做一次性重算（`app_settings['product.status_backfill']` 标记，幂等），不做 SQL 近似。

### 4.5 搜索（为什么不引入 FTS）

- 输入形态：中文 2 字（"沙发"）与 SKU 码（"ABC-123"）都常见。
- SQLite 内置分词器对 CJK 的实测结论：`unicode61/simple` 把连续中文当一个 token（"真皮沙发"整体成词，搜"沙发"不命中）；`trigram` 支持子串但 **MATCH 要求 ≥3 字符**，2 字查询直接落空——对中文商品名反而**更差**。
- 因此本版选：`title LIKE %kw% OR sku_code LIKE %kw% OR barcode LIKE %kw%`（本地）/ `platform_title LIKE %kw% OR platform_product_id LIKE kw%`（平台），配合 300ms 防抖、单次查询上限、结果计数。
- **性能预算与升级触发**：P95 ≤ 200ms @ 1 万商品行（实测验收项）；若 P95 > 200ms 或行数 > 2 万 → 再评估"trigram FTS（≥3 字）+ 2 字走 LIKE"的混合方案。**先实测、再优化，不预支复杂度。**

### 4.6 导出 / 导入（R3）

- **导出 CSV**：范围=选中或当前筛选；列：标题 / 副标题 / 品牌 / 本地分类 / 标签 / 状态 / 规格 / 价格 / 库存 / SKU 码 / 条码 / 挂载平台 / 更新时间。UTF-8 BOM + `escapeCsvCell` + **公式注入防护**（`= + - @` 开头加前缀，复用发票中心经验）。图片不进 CSV（列给本地路径或"N 张图"计数）。
- **导入 CSV**：模板下载 → 解析 → **预览 diff**（新增 / 更新 / 冲突）→ 确认 → 单事务落库 → 报告。匹配键：SKU 码优先、标题精确次之；更新为字段级（只写有值的列）；默认不下载图片。

### 4.7 缩略图渲染（新协议）

- 主进程注册只读自定义协议 `shopilot-media://`：仅映射 `userData/product-media/` 之下、路径规范化后仍在根内、扩展名白名单（jpg/png/webp/gif）的文件；其余一律 404。
- 渲染层 `<img src="shopilot-media://local/<相对路径>">`；CSP `img-src` 追加 `shopilot-media:`。
- 为什么不用 base64 data URL：列表几十行 × 每行几百 KB 会拖垮渲染；协议方案零拷贝、可利用浏览器缓存。
- 边界：product-media 文件缺失（被手动删）→ 显示占位 + "文件缺失"角标（如实，不报错反复重试）。

  → [确认执行] → 单事务落库 + draft_hash 重算 + 审计
  → 回执："成功 12 / 跳过 2 / 失败 0"（失败列原因）+ 列表刷新

```

### 5.4 删除与恢复（场景 E）

```
行 ⋯ → 删除 → 确认弹层（写明可恢复、台账保留、挂载将解绑）
  → 移入回收站（列表消失）
  → 回收站 Tab → 找到 → [恢复] → 回到本地列表（状态重算；挂载不自动恢复）
  → 若确要清掉：无发布记录的商品在回收站里提供[彻底删除]（有记录则禁用+说明）

### 5.5 与发布流程的衔接（R8 重构，不改红线）

```
行操作「发布」/ 批量条「批量发布」→ 右侧发布抽屉（替代页面下部堆叠面板）

  抽屉可关闭再打开（状态由台账驱动，不依赖页面挂载——修掉现有"panel 永远不出现"注释里记录过的坑）
```

## 6. 关键约束

### 6.1 不可动（回归防线，重构后逐条核对）

1. 发布**永远**由用户在浏览器提交（IPC 面不存在任何"替你提交"的入参——现行注释 §7.9 的落点不动）；
2. 归并必须人工确认，绝不自动合并；恢复不自动重新归并；
3. 平台值与本地值冲突不覆盖；抓不到 = null / unknown / 如实话术（不当 0、不猜）；
4. 软删 + 发布台账保留（彻底删除只对无发布证据的商品开放）；
5. 渲染层不碰 DB / 平台页面，全部走 IPC（含查询参数白名单）；
6. 媒体安全：SSRF 校验 / sha256 去重 / 只删应用自己的文件 / 孤儿清理需用户确认。

### 6.2 新增约束

| 面 | 约束 |
| --- | --- |
| 批量 | 一律 预览 → 确认 → 回执 → 审计；上限：改价 200 / 标签 500 / 归档 500 / 删除 100 |
| 状态 | 单点重算 + 不变量测试（防死字段复发） |
| 搜索 | 防抖 + 预算实测（§4.5），超预算先量再优化 |
| 排序 | 白名单映射，不许拼接用户输入 |
| 缩略图 | `shopilot-media://` 只读、根内校验、扩展名白名单 |
| 锚点契约 | 现有 data-test 锚点要么保留、要么在同期更新对应脚本（§9.3 清单），不允许"改了就算" |
| 性能预算 | 列表 P95 ≤ 300ms @ 1 万商品；搜索 P95 ≤ 200ms；改价预览 ≤ 500ms/200 商品 |

### 9.3 现有验收资产影响分析（关键结论：**影响很小**）

实测（2026-10-15 逐脚本统计）：7 个核心端到端脚本（library / batch / media-queue / readback / detail / sync / media-crash）**全部不依赖本应用 UI 的 DOM 锚点**——其中 6 个纯 IPC 级驱动（CDP 里直接调 `window.shopilot.products.*`，与用户点 UI 走同一条路径）；`product-sync-real-verify` 的 DOM 代码是**平台页面**读取辅助（含 ShadowRoot 穿透），同样与本应用 UI 无关。其余 DOM 重的脚本（wizard-walk / probe / screenshot 系列）操作的都是**平台页面**——UI 重构不破坏它们。

唯一要做的是：新增 UI 的 data-test 锚点与既有锚点做出**留存清单**（沿用：`product-sync-<storeId>`、`product-row-<id>`、`product-save-as-<id>`、`local-product-<id>`、`local-edit-<id>`、`local-localize-<id>`、`local-preflight-<id>`、`product-editor`、`editor-title/price/stock/save`、`publish-preflight`、`preflight-field-<f>`、`publish-open-page/fill/gate`、`publish-confirm`、`publish-readback`、`readback-<f>`、`readback-accept-<f>`、`batch-create`、`publish-batch-panel` 及 batch-* 系列、`media-queue-*`、`media-cleanup`）；新增：`product-tab-*`、`product-search`、`product-filter-*`、`product-sort`、`product-pager-*`、`product-batch-bar/price-*/tags/archive/export/delete`、`product-trash-*`。

## 附录 A · 批量改价规则细节

```
输入：productIds（≤200）；mode ∈ {percent, amount}；value；floorMinor（默认 1）
percent:  -90 ≤ value ≤ 1000（%），new = round(old × (1 + value/100))
amount:   ±10,000,000 分以内，new = old + value
统一：    new = max(new, floorMinor)；old 为 null → 跳过并计数（不猜、不当 0）
预览：    影响商品数 / 变体数 / 跳过数 + 前 10 条 diff + 全局最低与最高价变化
执行：    单事务；每商品重算 draft_hash + updated_at；审计 product.library.batchPrice（只记计数）
不做：    撤销（回执注明可反向再调）；不写平台（发布流程负责平台侧）
```
