fix(invite): 微信小店邀约「一位都没邀出去」——把"不可邀约"与"页面没渲染"分开；发布 0.4.28

现象：点「开始邀约」跑满几分钟、看着正常，最后报失败且一位都没邀约
（实测记录：6 轮全失败，报 continuous 6 次 TASK_DAREN_PAGE_UNOPENABLE）。

根因（真机逐页量取）：同一张达人详情页，按钮在不在取决于**这位达人本人**——
  · 可邀约          → 蓝底「邀请带货」按钮
  · 不达合作门槛    → **没有按钮**，写着「暂未到达合作门槛」
  · 7 天内已邀约过  → 按钮**在**但是灰色禁用，悬浮说明「你已经邀请过该达人，7天内不可再次发送带货邀约」
引擎此前只有一种解释：找不到按钮 = 页面（微应用）没渲染出来 → 退避重试**同一位**，
连试 N 次即判定"平台整体异常"整单失败。广场里前两种大量存在（一屏 20 位里前两位就是），
于是必然卡在第 1 位出不去。

引擎（都加在通用原语上，不写平台 if）：
- clickByText.absentText + absentCode：目标缺席时，若页面上出现这段**替代文案**，
  立刻按专属错误码失败、**不等到超时**——"这位天生不可用"与"页面还没渲染出来"处置相反，
  必须分开。判据收紧为"只认本身就在说这句话的元素"（见 ABSENT_FN），
  避免退化成"页面上出现过这几个字"。
- loop.onCode.advance：新增恢复语义"重开本轮但**保留**已访问记录" = 跳过这一位换下一位。
  与 restart 只差这条记录：restart 回滚它是为了重试同一位（限流退避），
  advance 保留它才能真的换人，否则原地打转直到耗尽次数。
- disabledCode 用起来：详情页按钮禁用 → TASK_DAREN_ALREADY_INVITED，同样 advance 跳过；
  并让引擎**读出平台给的禁用原因**（按钮旁 popover）写进消息，排查时能区分
  "已邀约过"与"额度用完"（此前都显示成一句"平台限制该操作"）。
- advance 连续撞满上限 → **干净收尾**（run 成功 + stopReason 如实记录），不报失败：
  判据是平台自己写明的"不可邀约"文案，是确定性信号、不是渲染故障。
- 嵌套步骤的 retryLimit 生效：真机跑到第 25 轮时 aiGenerate 超时把整批（前 24 位已真实发出）
  打成 failed。现在循环体内声明了 retryLimit 的子步骤会先重试（AI 生成话术幂等，给 2 次）；
  非幂等步骤（点击/输入）绝不重放。
- 新错误码 TASK_DAREN_NOT_INVITABLE / TASK_DAREN_ALREADY_INVITED。

面板：展开邀约记录时 loop 步骤多一行「成功邀约 N 位 · 跳过 N 位（不达合作门槛 / 7 天内已邀约过）
· 因「…」正常收尾」——被跳过的达人不出现在任何步骤成功里，不说明就分不清
"跳过了几位"和"平台不给发了"。

真机验证：
- 真实发出 **24 位**：平台「我的邀约 → 邀请中」14 → 38（+24），时间戳 16:24–16:33 与运行窗口对得上。
- 当前构建单轮端到端复验成功，留档截图是平台的「已成功发送邀约」，邀请中新增 1 条（17:46）。
- 跳过判据受控验证：对已知不可邀约达人 **8.1 秒**就报出专属码（不是等满 60s 的"找不到"）；
  同一地址真没渲染时仍走退避重试（两条路径都在）。
- advance 语义受控验证：留下 2 条"跳过这一位并重开本轮"记录后干净收尾。
- 单测 118 项全过（新增缺席判据 7 项、advance/禁用码接线、以及"生成的步骤能真的创建任务"守卫——
  onCode.limit 曾因超过 schema 上限被 create 静默拒绝，表现成"点开始邀约没反应"）。
